## 1. ⚙️ 프로젝트 구성 및 디자인 프로세스

### 🎨 디자인 리뉴얼 과정

1. **기존 사이트 분석 & 벤치마킹:** 기존 라운즈 사이트의 레이아웃, 정보 구조(IA)의 아쉬운 점을 파악하고 타 글로벌 아이웨어 커머스를 벤치마킹하여 시각적 몰입감을 높이는 방향으로 컨셉을 설정했습니다.
2. **UI/UX 리뉴얼 방향:** 메인 배너 및 타임 세일 영역의 스케일감 조절, 브랜드 스토리 강조를 위한 비주얼 강화, 직관적인 내비게이션 구조 재설계.
3. **디자인 시스템 구축:** 일관된 사용자 경험을 제공하기 위해 컬러 가이드(`--main--color`, `--font--color` 등), 타이포그래피 규칙, 컴포넌트(`var(--base-unit)`) 단위를 정의하여 스타일 코딩에 반영했습니다.

### 🛠 기술 스택 (Tech Stack)

- **Design:** Figma
- **Frontend:** HTML5, CSS3 (Advanced Flexbox/Grid, Media Queries), Vanilla JavaScript (ES6+), Swiper.js
- **Data:** JSON (상품 정보 및 브랜드 데이터 비동기 연동)

## 3. 🖥️ 사용법 및 주요 구현 기능

- JSON 데이터 기반 동적 렌더링: 브랜드별 상품 데이터, 할인율, 가격 정보를 data/products.json 파일로부터 비동기로 받아와 화면에 동적으로 카드를 바인딩합니다.
- 한정 특가 실시간 타이머: 이벤트 마감 시간을 기준으로 남은 일, 시, 분, 초를 실시간 계산하여 화면에 반영하는 자바스크립트 타이머를 구현했습니다.
- 인터랙티브 슬라이더: Swiper.js를 커스텀하여 PC 환경에서는 활성화된 중앙 카드가 확대되는 시각적 효과를 부여하고, 모바일에서는 스크롤바와 스와이프에 최적화되도록 설계했습니다.
- 폼 유효성 검사: 로그인 및 회원가입 시 정규표현식을 활용한 이메일 형식 검사, 비밀번호 복잡도 실시간 체크 가이드 애니메이션을 구현했습니다.
- 장바구니: 사용자가 선택한 상품 정보와 수량을 브라우저의 localStorage에 보관하여, 페이지를 새로고침하거나 브라우저를 껐다 켜도 담아둔 상품 리스트가 안정적으로 유지되는 장바구니 기능을 구현했습니다.
- 카테고리 필터링 시스템: 사용자가 원하는 브랜드, 안경태 형태, 재질 등을 선택하면 매칭되는 JSON 데이터만 실시간으로 선별하여 화면을 재구성하는 필터링 기능을 구현했습니다.

## 4. 🐛 버그 및 디버그

개발 및 크로스 브라우징 테스트 과정에서 발견된 주요 이슈와 해결 방법(트러블 슈팅) 기록입니다.

크로스 브라우징 이슈 (Flexbox 정렬 꼬임)

- **현상:** 특정 모바일 기기 및 구형 사파리 브라우저에서 타이머 블록의 가로폭이 수축하고, 숫자와 라벨이 무너져 콜론 배지와 겹치는 현상 발생.
- **해결:** 인라인 속성을 가진 span 태그들을 display: block으로 제어하고, 부모 컨테이너에 flex-shrink: 0과 강제 여백을 부여하여 모든 기기 환경에서 레이아웃 정렬을 견고하게 방어했습니다.

배경 이미지 로딩 지연에 따른 UX 저하

- **현상:** 고해상도 리뉴얼 배경 이미지(.png) 적용 시, CSS 파싱 이후에 이미지가 다운로드되어 화면이 순간적으로 하얗게 뜨는 문제 발견.
- **해결:** 압축률이 높은 최신 이미지 포맷인 .webp로 변환하여 파일 용량을 획기적으로 줄이고, HTML <head>에 <link rel="preload"> 설정을 추가해 브라우저가 배경 이미지 로드를 최우선으로 처리하도록 개선했습니다.

## 5. ❓ FAQ

Q. 데이터 연동에 사용된 JSON 파일은 어떻게 구축했는지?

> A. 실제 상용 서비스 수준의 완성도 높은 데이터를 보여주기 위해, 기존 라운즈 공식 웹사이트의 상품 데이터들을 직접 크롤링하여 추출했습니다. 파싱된 원본 데이터를 이번 리뉴얼 디자인 컴포넌트 구조에 최적화되도록 객체 구조로 커스텀 가공하여 products.json 파일셋으로 빌드했습니다.

Q. 장바구니에 담은 상품 데이터는 백엔드 DB에 저장되는지?

> A. 아닙니다. 순수 프론트엔드 중심 프로젝트이므로 브라우저 고유의 저장소인 Web Storage API (localStorage)를 활용해 가상 데이터베이스 역할을 하도록 설계했습니다. 덕분에 페이지 전환 시에도 데이터가 유지됩니다.

Q. 미디어 쿼리(반응형) 기준점은 어떻게 되는지?

> A. 모바일(480px 이하), 태블릿(481px ~ 768px), PC(769px 이상)의 3단계 브레이크포인트를 설정하여, 각 디바이스 가로 해상도 환경에 맞춰 디자인이 완벽하게 최적화되도록 반응형 웹을 구현했습니다.
